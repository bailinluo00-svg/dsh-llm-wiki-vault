# 收件箱 — Inbox

**把新的文章丢进这个文件夹，然后告诉 DSH「处理收件箱」，剩下的交给它。**

支持的类型：`.pdf`、`.md`、`.markdown`、`.txt`、`.html`、`.htm`。
不需要改文件名、不需要分主题、不需要建子目录——直接丢进来就行。

---

## 怎么用

### 最省事的方式

1. 把文件复制/拖进本目录
2. 跟 DSH 说一句：

   > 处理收件箱

   DSH 会按 `AGENTS.md` 的 Ingest 流程走完：识别元数据 → 归档到 `raw/<主题>/` → 对照 wiki 做 triage →
   编译知识页 → 更新索引与导航页 → 记日志 → 跑证据保真自检，最后向你汇报建了/改了哪些页面。

### 你自己想看脚本识别到什么

```powershell
$env:PYTHONPATH="D:\DSH\.tools\pylibs"
$t = "<你的仓库>\tools\ingest_files.py"

python $t --plan                    # 只报告：每个文件识别到的标题/作者/类型 + 推测主题，不写任何文件
python $t --topic <主题> --dry-run   # 预演：显示将写入的 raw 路径，不写文件
python $t --topic <主题>             # 真正执行（只做机械部分：归档 + 生成 raw 文本）
```

`--topic` 之后那一步才是编译，需要我来做判断。

## 规则

| 规则 | 说明 |
|---|---|
| **处理后文件会被移走** | PDF 移到 `raw/<主题>/pdfs/`，文本/HTML 移到 `raw/<主题>/_source/`。所以**收件箱是空的 = 全部处理完了** |
| **不要在这里整理、改名、分类** | 那是脚本和我的事。放进来就别管了 |
| **可以放子目录** | 浏览器或 Zotero 导出的嵌套目录会被自动摊平 |
| **未下载完的文件会被忽略** | `.crdownload` / `.part` 不会被误处理 |
| **本目录不进知识库** | `inbox/` 不在 `raw/` 也不在 `wiki/`，不属于知识页，也不参与 grounding 校验 |
| **只增不改** | 文件一旦被处理进 `raw/`，就成为不可变素材；要更正只能新增素材并走 Disputed 流程 |

## 为什么收件箱在 `raw/` 外面

`raw/` 的契约是「**已经入库的、不可变的原始素材**」。如果把未处理的文件放在 `raw/` 里：

- 无法区分「哪些还没处理」
- 破坏了「raw 里每一份素材都有对应知识页或已记录 No material」的可审计性
- 会让证据保真检查把未处理的文件也算进素材范围

所以收件箱与 `raw/` 平级，作为**暂存区**存在。这个划分是刻意的。

## 主题目录名怎么定

主题是**知识库层面的判断**，不是文件属性——所以脚本不猜，由我按 `AGENTS.md` 第 2.1 节的规则决定：

- 先看 `raw/` 下已有主题目录，**能复用就复用**
- 只有确实是新领域时才新建（保持主题目录少而稳定）
- 命名用 kebab-case 英文，如 `example-topic`、`example-topic-2`

目前已有主题：`example-topic`（4 篇）、`example-topic-2`（3 篇）。

## 需要 OCR 的扫描件怎么办

`ingest_files.py` 靠 **PDF 文本层**提取正文。**纯图片扫描件会提取出空白**。

如果丢进来的 PDF 没有文本层，我会告诉你，那时可选：

1. 用 Obsidian 插件的 PDF 转换能力（设置里开启 `forcePdfSupport` / `writePdfMarkdownToVault`）
2. 你自己用 OCR 工具转成文本后再丢进来
3. 我先把 PDF 归档、只记录元数据，正文留待后续补

**扫描件不会静默失败**——脚本和自检都会发现空正文。

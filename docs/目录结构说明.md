## 2. 三层结构与所有权

| 层          | 路径                                    | 谁写                           | 谁能改      | 不可违背的规则                                     |
| ---------- | ------------------------------------- | ---------------------------- | -------- | ------------------------------------------- |
| 素材层        | `raw/**`                              | Agent 写入一次                   | **无人可改** | 逐字保真；一篇素材一个文件；元数据头含来源/采集日期/发布日期             |
| 编译层（Agent） | `wiki/<topic>/**`                     | Agent                        | Agent    | 只一层主题目录；每页有 `Raw:` 承重字段；grounding invariant |
| 编译层（插件）    | `wiki/{entities,concepts,sources}/**` | 插件 LLM                       | 插件       | Agent 不写入、不手改                               |
| 索引层        | `index.md`（根）                         | `tools/sync_index.py` + 手写章节 | Agent    | 表内自动、表外手写                                   |
| 索引层        | `wiki/index.md`                       | 插件                           | **无人**   | 格式是插件 Query 引擎的解析契约，改成表格会让 Query 失效         |
| 日志层        | `log.md`                              | Agent 与插件                    | 只追加      | 不改写既有条目                                     |

### 为什么主题目录必须叫 `wiki/<topic>/` 而不是 `wiki/concepts/`

插件的 `wiki/concepts/` 是**它自己的概念页命名空间**：它会在重新摄取时用 LLM 重写其中的同主题页面。
如果 Agent 把编译结果也写进去，下一次插件 Ingest 就可能覆写掉经 grounding 校验的长文。
因此 `wiki/<topic>/` 是刻意的隔离带——代价是插件的 Query Wiki 面板看不到这些页面，
但 Agent 侧的 Query（读根 `index.md` + 全文检索）可以完整覆盖它们。

### 已知偏离与理由

1. **全局索引位置**：`wiki/index.md` → 仓库根 `index.md`。原因是插件对该路径有强占用与覆盖行为，
   且其 Query 引擎以该文件的 bullet 列表为唯一检索入口（源码正则：
   `^- \[\[([^\]|]+)(?:\|[^\]]+)?\]\]\s*(?:`aliases: ...`)?(?:\s*-\s*(.+))?$`）。
   放在根目录后，两个索引各司其职、互不干扰，且根索引仍覆盖 `wiki/` 下全部编译页面。
2. **索引行格式**：根 `index.md` 用 Markdown 表格（对齐 `references/index-template.md`），
   而非插件的 bullet 列表。表格行由 `tools/sync_index.py` 从页面 frontmatter 与 Overview 生成。
3. **页面 frontmatter 用 YAML**：skill 模板用引用块描述元数据。本仓库两者都保留——
   YAML 供 Obsidian 属性面板与 `sync_index.py` 使用，引用块供人阅读与 grounding 校验定位。
4. **日志双格式共存**：skill 的条目格式与插件条目格式写在同一个 `log.md` 中，靠标题行的结构区分
   （插件是 `[YYYY-MM-DD HH:MM] ingest | 标题 · 指标`，Agent 是 `[YYYY-MM-DD] ingest | 标题` + 缩进子项）。
5. **主题目录与插件子目录并存**：`wiki/` 同时容纳两类页面体系，靠目录名区分所有权。

## 4. 索引机制

两个索引，各答一个问题：

| 索引 | 回答的问题 | 谁维护 | 格式 |
|---|---|---|---|
| 根 `index.md` | 「我要找的是哪一页？」（人的目录） | `tools/sync_index.py` + 手写 | 按主题分节 + 表格（Article / Summary / Updated） |
| `wiki/index.md` | 「有哪些页面可以检索？」（插件的检索入口） | 插件自动 | H2 分节 + bullet 列表 `- [[folder/name\|name]] - summary` |

根索引的生成规则：

- `## wiki/<topic> — <中文名>` 分节；分节下的一句话说明与 Summary 覆盖来自 `tools/topics.yaml`。
- 表格行：Article 取页面 frontmatter 的 `title`；Summary 优先取 frontmatter 的 `summary`，否则取
  `## Overview` 的首句（按句号截断到 100 字以内）；Updated 取 frontmatter 的 `updated`，
  缺失时回退到文件修改日期。
- `python tools/sync_index.py --check` 只报告漂移（退出码 1），用于 Lint。

## 5. 日志格式

`log.md` 是追加式，两套系统的条目并存：

```markdown
## [2026-09-21] ingest | 示例领域的全局韧性分析示例（EXA）        ← Agent 条目
- Disposition: New
- Raw: raw/example-topic/2016-example-global-resilience-analysis.md
- Updated: 示例页面 A

## [2026-09-21 14:32] ingest | WDS resilience · 28s · claude-sonnet-4-5 · 4.2KB   ← 插件条目
**Created pages**：[[concepts/X]]
**Updated pages**：[[entities/Y]]
```

要点：

- `- Disposition:` 四值：`New` / `Update` / `Disputed` / `No material`。
- `No material` 的标题必须逐字写成 `## [YYYY-MM-DD] ingest | no material: <raw 相对路径>`——它是机器可读的清单键。
- 没有涟漪更新时省略 `- Updated:` 行。
- 插件的条目带 `HH:MM` 与性能指标，且会在文件超过 512 KB 时裁掉最旧条目；因此**重要结论写进知识页，不要只留在日志里**。

## 6. 与插件相关的硬约束速查

| 插件行为（源码事实） | Agent 的应对 |
|---|---|
| 每次 ingest 用 `# Wiki Index` + bullet 列表**整文件覆盖** `wiki/index.md`（`vault.process`） | 该文件末尾的 AGENT 登记段会在插件 ingest 后被抹掉，需重跑 `sync_index.py --bridge-index` 恢复 |
| Query 引擎只解析 bullet 列表行 | 永不把它改成表格 |
| 只索引 `wiki/{entities,concepts,sources}` | 编译长文只放 `wiki/<topic>/` |
| 正文禁止 `[[sources/...]]` | 溯源只走 `Raw:` 与 frontmatter `sources:` |
| `wiki/log.md` 超 512 KB 裁旧条目 | 日志条目保持简短 |
| 自动维护 `wiki/schema/config` 词表（已初始化，v1） | 插件页面 `tags` 必须取自词表；`wiki/<topic>/` 页面不受此约束，但仍统一用 `example-domain/<子类>` 斜杠命名空间 |
| `ensureWikiStructure()` 会创建 `wiki/{entities,concepts,sources}` 与 schema | 不要手工创建或删除这些目录 |
| Lint 会删除「空 stub 页」但跳过 `reviewed: true` 的页面 | Agent 页面若需保护，可加 frontmatter `reviewed: true` |
| schema 要求插件页面文件名 slug 化、且实体/概念名不翻译 | 仅适用于 `entities/`、`concepts/`、`sources/`；`wiki/<topic>/` 页面用中文标题命名（Obsidian 对中文与空格支持良好） |

### 一次插件摄取的全量核对结论（双轨隔离成立）

用一篇测试笔记跑完整摄取后逐项核对：

| 核对项 | 结果 |
|---|---|
| Agent 编译页、`raw/`、根 `index.md`、`log.md` 的字节数 / 条目数 / 修改时间 | **完全未变** |
| 插件写入范围 | 只新增 `wiki/{entities,concepts,sources}/` 15 页 + 首次生成 `wiki/index.md` |
| `raw/` 是否被当作源目录 | 否 |
| 摄取后索引与证据保真 | 仍同步 / 仍 0 疑点 |
| 插件侧溯源机制 | `sources/` 页 frontmatter 用 `source_file: "[[<原笔记>.md]]"` + `contentHash`，**不引用 `raw/`** |

**已知需要警惕的插件行为**：LLM 会自行推断别名（实测给作者编了一个原文没有的音译名）、会把被摄取的笔记本身也建成实体页、正文会出现裸链接。**插件页面不是可靠来源，引用前必须回 `raw/` 核实。**
